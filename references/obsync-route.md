## 路线与实现锚点

```text
小程序手动提交文章链接
        ↓ 提交/服务端采集细节未观察
第三方处理服务（插件固定指向 ob.agentok.top）
        ↓ GET /v2/sync/articles，取得已处理记录
本地插件写 Markdown、可选下载图片
        ↓ 写入完成后 POST /v2/sync/articles/{id}/ack
Obsidian 本地文件
```

本机发布包锚点：`main.js` 的 `loadSettings`（约 163 行）固定 API base；`runSync`（约 232 行）拉列表、按 `sync_id` 找已有文件、写入后 ACK；`writeArticle/updateArticle`（约 339/359 行）保存 Markdown；`localizeImages`（约 392 行）独立下载正文图片；`apiRequest`（约 536 行）使用 Bearer 认证。

这里的列表是用户待同步内容，不是人民日报等公众号的历史列表。不能假定有整号分页、最近 100 篇、批量提交 API、并发能力或频率保证。没有观察到服务端采集请求，**不得将图片请求头当作正文抓取的反爬方案**。本机修改 API 配置会在 `loadSettings` 被固定值覆盖，不能将该包描述为已支持任意自托管后端。

## 线上验收门槛

工具明确禁止访问某个目标时停下该在线路径，不能换成小程序、代理或 Firecrawl 继续获取同一受限目标。可分析用户正常导出的本地文件；不让用户提供登录态/抓包密钥。

工具允许且用户明确选择第三方同步后，先取得数据传出去向确认：公开文章链接及相关元数据会交给所选服务，绑定账户参与请求；不授权上传私人笔记、私聊、剪贴板或整个 vault。使用手动输入明确的公开 URL，避免“一键读取剪贴板”意外提交私人内容。若现有笔记库可能自动拉取并改写待同步文件，先说明这一影响，优先隔离测试库；不自动改动已有绑定。

随后少量逐条测试，记录每篇的公开文章身份、账号、发布时间、正文头尾段和图片结果。小程序保存提示 → 服务记录 → 本地 Markdown → 正文核对必须分别取证。至少 3 篇普通图文与 1 篇边界样本通过后才扩量。遇登录、验证码、访问限制或额度问题暂停，不用换出口/账号规避。

本机先前公众号测试曾遇到工具访问限制，故没有用本路线提交受限目标。当前代理发起并完成的在线采集数仍为0；已有本地导出核验单独计数，不能写成“实测绕过反爬”或“已获取人民日报最近100篇”。

## 接入本技能的数据约定

只处理用户明确选定的导出文件/目录，不读取插件 `data.json`、令牌或整库内容。先核验实际 frontmatter；默认映射：

第一步先按 `source_url` 校验平台。目录名、文章标题和 `parse_status: ok` 都不是平台身份依据。Obsync可收集其他网页/随笔/文件，非公众号内容另列，不改造假链接混入本技能计数。来源链接可能包含签名/分享追踪参数，日志和公开结论只保留必要的脱敏平台信息。

| Obsync 导出字段 | 本技能字段 | 处理条件 |
|---|---|---|
| `source_url` | `url` | 只接受本技能支持的公众号公开文章链接 |
| `title/account/author` | 同名 | 只取实际存在值 |
| `published_at` | `published_at` | 缺失留空，不拿 saved_at 或文件名补发布时间 |
| frontmatter 之后的正文 | `content_md` | 保留正文；检查是否仅有标题、错误或占位文本 |
| `parse_status` | `status` | 不能直接原样复制；ok 且有真实正文才为 ok；空正文为 missing_body；其他未知值待人工核查 |

`saved_at` 是保存时间，不等于本次抓取时间，不能无依据复制为 `fetched_at`。缺少 parse_status、用户自定义模板或内容结构不符时先人工核查，不静默算成功。附件相对路径必须按最终归档位置处理；图片请求失败可能保留远程链接，单有 Markdown 文件不能称离线完整。

规范化 JSONL 后再运行 `scripts/organize_exports.py`。第三方服务绑定、提交、下载正文、本地整理和公开 Git 是独立授权/验收层；公开仓库只放原创技能、脱敏技术结论，不放文章正文、队列、vault 路径、账号或凭据。
