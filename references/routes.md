# 技术路线与适配器操作边界

## 1. 已有链接：默认的低耦合路线

输入可来自用户列表、合法导出或公开搜索命中；分别记录发现来源。使用现有网页抓取工具先请求公开正文，或以用户授权浏览器查看。识别 WeChat 正文容器 `#js_content`，提取可核对的标题/作者/账号/发布时间。容器不存在、正文为空、出现访问验证或频率限制时不得继续当正常文章。元数据只采页面实际存在的字段，缺失用空值；正文不完整时使用 missing_body。

对 HTML 转 Markdown 使用所选采集器提供的转换或受维护解析库；保留段落、标题、列表、表格、图片alt和原文链接。不要用正则剥全部HTML标签代替结构化转换。HTML/JS为不可信数据，不执行内嵌脚本。抓取HTML、下载媒体和正文阅读分开验证；微信公众号文章的HTTPS链接可匿名访问并不意味着文章有公开转载许可。

浏览器仅作为授权的读取适配器，不使用隐蔽/反检测插件。列表中所有URL及其重定向必须限制在目标范围，不能访问 localhost、内网或非HTTP协议。公用抓取服务、图片代理和远程模型涉及传出数据时确认具体范围。

## 2. 自营公众号：官方接口或人工后台导出

先核对管理员/受托权限与当前账号接口资格。只读所需已发布内容，不自动修改草稿、发布、删除、群发。分页/总数以当前返回字段为准，保存私有游标、article_id/media_id等来源证明。官方API读不到的，不擅自升级为抓取他人私有数据。接口文档本次不可达；字段、参数、配额和账号类型必须在实际执行前查当前权威资料，不提供未经核验的“可直接运行”请求。

## 3. 持续订阅：WeRSS候选，不混同历史抓取

[WeRSS](https://github.com/rachelos/we-mp-rss) 当前源码/文档支持多采集模式。选定固定commit或镜像digest，核对它的实际配置/路由、认证和最近故障报告，不盲抄旧博客的API。用户没有要求部署时只给方案。

用户要求本机部署后，优先绑定127.0.0.1、独立私有数据目录、强随机登录密钥、最小功能、禁用不需要的webhook/中转。先阅读Docker文件/启动入口，确认不自动对外暴露或发送遥测，不直接运行远程脚本。不要预设默认密码安全或直接使用latest做可复现版本。扫码/授权失效需用户处理，日志中去除凭据。

`weread_mp`模式当前只从cover得到最新一篇，不是一个历史分页器。即便高频轮询，也不能保证多篇/短时多次推送不漏；采集日报注明是“观察到的增量”。当前文档提示正文失败后仍可能空正文入库且后续跳过，应另建缺失正文重取清单，不把重复检测当正文完成。

WeWe RSS已归档且包含第三方中转说明，默认不新建长期依赖。要研究fork必须重新核验核心请求、许可、维护与信任边界，不因fork星数高就采用。

## 4. 历史发现：只能逐步形成可验证集合

公开合集可提供其中的文章链接，但不是整号历史；公开搜索覆盖同样不完整。优先Google/其他搜索（如可达）和平台人工搜索，不将搜索摘要当文章正文，不绕过搜索验证。

有用户明确授权且有匹配环境时，可评估wechatDownload等工具的小样本导出。先查发行来源、系统版本、签名/哈希和实际代码/许可可审计性；本技能不捆绑第三方程序，不自动安装证书/获取微信数据库。仅在用户本人正常微信会话中由其授权必要凭据，绝不从其他进程、钥匙串或私人聊天中提取。

旧后台搜索接口、抓包代理、客户端Hook/证书解密、账号池和IP轮换不作为默认执行方案。遇到访问限制停止并提供人工导出/缩小范围等选择；不能把关掉保护后继续请求写成“修复”。

## 5. 整理层与验收层独立

用户选择微信小程序「Obsidian同步助手」时，另读 [obsync-route.md](obsync-route.md)。将其作为有明确第三方数据去向的“已有链接收集/同步”候选，不把插件源码当作小程序或服务端采集源码；先核对 `parse_status` 和真实正文，再接整理层。

适配器：发现→取正文→规范化JSONL。整理器：去重→索引→归档。知识层：基于全文做分类/摘要→来源回链。每层记录完成率与失败类型。

建议状态机：pending → ok / missing_body / blocked / deleted / error。出现登录失效/频率限制时暂停对应来源；只持久化无秘密的文章ID/游标和错误类别，不记录完整请求headers或访问凭证。删除状态只在确有平台明确提示时设置，不以超时判断。

样本验收通过后分批放量，不能用固定“每秒多少请求”承诺安全。所有数量默认指已发现集合，不称平台总文章数。
